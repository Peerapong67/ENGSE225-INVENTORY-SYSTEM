## ส่วนที่ 3: การทดสอบถอยเวอร์ชันบน Git (Rollback)

### RB-1 ถอยการแก้ไขที่มีข้อบกพร่องด้วย `git revert`

| ขั้นตอน | ผลที่เกิดขึ้น |
| :--- | :--- |
| ก่อนเกิดเหตุ | commit `441b2ea` ชุดทดสอบผ่าน 158 รายการ |
| จำลองการปล่อยโค้ดที่มีข้อบกพร่อง | commit ทดลองแก้ `is_low_stock()` จาก `<=` เป็น `<` ในไฟล์ `product.py` เพียงไฟล์เดียว |
| ผลการทดสอบ | **ไม่ผ่าน 2 รายการ** ได้แก่ กรณีขอบเขต `quantity == reorder_point` ใน `test_product.py` และ `test_inventory_app.py` (ชุดทดสอบตรวจพบข้อบกพร่องได้) |
| ถอยเวอร์ชัน | `git revert --no-edit HEAD` สร้าง commit ใหม่ที่ย้อนการแก้ไข |
| หลังถอยเวอร์ชัน | ชุดทดสอบผ่าน 158 รายการ ใช้เวลา 2.8 วินาทีนับจากสั่ง revert และ `product.py` ตรงกับก่อนเกิดข้อบกพร่องทุกไบต์ |
| ประวัติการแก้ไข | ยังเก็บทั้ง commit ที่มีข้อบกพร่องและ commit ที่ถอยไว้ สามารถตรวจสอบย้อนหลังได้ |

> การซ้อม RB-1 รอบแรกใช้ไม่ได้ เนื่องจากคำสั่ง `git revert` ไม่รองรับตัวเลือก `-q` และคำสั่ง `git commit -am` นำไฟล์อื่นเข้า commit ทดลองด้วย จึงซ้อมใหม่โดยระบุเฉพาะ `product.py` ผลของทั้งสองรอบบันทึกไว้ในหลักฐานดิบ บทเรียนนี้สนับสนุนข้อเสนอให้ระบุไฟล์ทุกครั้งเมื่อ commit

### RB-2 ถอยกลับไปเวอร์ชัน 2.0.0 แล้วกลับมาเวอร์ชัน 2.0.1

| ขั้นตอน | ผลที่เกิดขึ้น |
| :--- | :--- |
| ถอยกลับไปเวอร์ชัน 2.0.0 | สร้าง worktree ที่ commit `c76c7b7` ชุดทดสอบของเวอร์ชันนั้นผ่าน 145 รายการ |
| ความเข้ากันได้ของข้อมูล | เปิดฐานข้อมูลที่สร้างโดยเวอร์ชัน 2.0.1 ด้วยโค้ดเวอร์ชัน 2.0.0 ได้ (exit code 0) แสดงสินค้าครบ 4 รายการ เพราะทั้งสองเวอร์ชันใช้โครงสร้างฐานข้อมูลเดียวกัน |
| กลับมาเวอร์ชัน 2.0.1 | ชุดทดสอบผ่าน 158 รายการ |

**ข้อควรระวัง:** การถอยเวอร์ชันที่ข้ามการเปลี่ยนแปลงโครงสร้างฐานข้อมูลอาจไม่เข้ากันได้ ระบบยังไม่มีกลไกปรับโครงสร้างฐานข้อมูล (migration) ต้องสำรองฐานข้อมูลก่อนถอยเวอร์ชันทุกครั้ง

## ส่วนที่ 4: ข้อค้นพบและข้อเสนอแนะ

| ลำดับ | ข้อค้นพบ | ความเสี่ยง | ข้อเสนอแนะ | การบันทึกที่เสนอ |
| :---: | :--- | :--- | :--- | :--- |
| 1 | เมื่อไฟล์ฐานข้อมูลเสียหาย โปรแกรมหยุดทำงานพร้อมข้อความ Traceback ซึ่งผู้ใช้ทั่วไปไม่เข้าใจ (DR-1) | ผู้ใช้ไม่ทราบวิธีแก้ไข | ตรวจจับ `sqlite3.DatabaseError` ตอนเปิดฐานข้อมูล แล้วแสดงข้อความแนะนำให้กู้คืนจากไฟล์สำรอง | เสนอเปิด **BUG-109** (ระดับเล็กน้อย) |
| 2 | เมื่อไฟล์ฐานข้อมูลถูกลบ โปรแกรมสร้างฐานข้อมูลว่างใหม่โดยไม่แจ้งเตือน (DR-2) | ผู้ใช้อาจทำงานต่อบนฐานข้อมูลว่างโดยไม่รู้ว่าข้อมูลหายไป | แจ้งเตือนเมื่อสร้างฐานข้อมูลใหม่ และให้ยืนยันก่อนดำเนินการ | เสนอเป็นความต้องการใหม่ **FB-06** ใน Future Backlog |
