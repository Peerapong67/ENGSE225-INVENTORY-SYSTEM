**มาตรฐานอ้างอิง:** ISO/IEC 12207 (กระบวนการส่งมอบระบบ การจัดการโครงแบบ และการปิดโครงการ), ISO/IEC 14764:2006 (การส่งต่องานคงค้างเข้าสู่รอบการบำรุงรักษา)
**รายวิชา:** ENGSE225 Software Evolution & Maintenance

## วัตถุประสงค์ของเอกสาร

เอกสารฉบับนี้กำหนดขั้นตอนการปล่อยระบบเวอร์ชัน 2.0.1 และการจัดระเบียบเครื่องมือดิจิทัลของโครงการ ได้แก่ คลังโค้ดบน GitHub และบอร์ดงานบน Jira เพื่อเตรียมความพร้อมสำหรับการปิดโครงการทางการบริหาร (Administrative Closure)

**วิธีใช้เอกสาร**
- ส่วนที่ 1 ตรวจสอบความพร้อมก่อนปล่อยระบบ
- ส่วนที่ 2 และ 3 เป็นรายการงานที่ต้องดำเนินการบน GitHub และ Jira ตามลำดับ ทุกรายการมีช่องสถานะสำหรับติดตามผล
- ส่วนที่ 4 และ 5 สรุปชุดเอกสารปิดโครงการและลำดับการดำเนินงาน

| **ผู้รับผิดชอบหลัก** | หัวหน้าฝ่ายเทคนิค (การปล่อยระบบและ GitHub), ผู้จัดการโครงการ (Jira และเอกสารปิดโครงการ) |

| การจัดระเบียบ branch (ส่วนที่ 2.4) | มี branch ที่รวมแล้ว 12 branch และ branch ที่ไม่ได้ใช้งานต่อ 1 branch | ลบ 13 branch โดยสร้าง tag สำรองให้ branch ที่ยังไม่รวมก่อนลบ |

**งานที่ต้องดำเนินการก่อนเป็นลำดับแรก**
1. หัวหน้าฝ่ายเทคนิคตรวจผล GitHub Actions ของ commit `73e7cfd` และแนบลิงก์ในเอกสารที่เกี่ยวข้อง

**ความเสี่ยงที่ต้องระวัง:** การลบ branch และการสร้าง tag มีผลกับคลังโค้ดบนเซิร์ฟเวอร์ทันที ต้องดำเนินการหลังผ่านเกณฑ์ R8 แล้วเท่านั้น และต้องสร้าง tag สำรองให้ branch ที่ยังไม่รวมก่อนลบทุกครั้ง

### 2.4 การจัดระเบียบ branch

ให้ลบเฉพาะ branch ที่รวมเข้า `main` แล้วและไม่มีคำขอรวมโค้ดค้างอยู่ **สำหรับ branch ที่ยังไม่รวม ต้องสร้าง tag สำรองก่อนลบ** เพื่อไม่ให้ commit สูญหาย

| branch บนเซิร์ฟเวอร์ | สถานะ | การดำเนินการ |
| :--- | :--- | :--- |
| `feature/Create-a-Product-class`, `feature/Create-the-Validator-class`, `feature/Create-the-Logger-class-Singleton`, `feature/Create-the-ProductRepository-class`, `feature/Refactor-InventoryApp`, `feature/Add-search-and-pagination-features` | รวมแล้ว (รอบพัฒนาที่ 1) | ลบ ☐ |
| `feature/barcode-reorder-point`, `feature/cr02-csv-export`, `bugfix/cr01-duplicate-barcode` | รวมแล้ว (รอบพัฒนาที่ 2) | ลบ ☐ |
| `feature/atomic-file-writing` | รวมแล้ว (PR #32) | ลบทั้งบนเซิร์ฟเวอร์และบนเครื่อง ☐ |

### 3.4 คำค้น JQL สำหรับตรวจสอบความเรียบร้อยของบอร์ด

ก่อนปิดโครงการ คำค้นต่อไปนี้ควรให้ผลลัพธ์ **0 รายการ** (หากรหัสโครงการบนบอร์ดจริงไม่ใช่ `SCRUM` ให้เปลี่ยนให้ตรงกัน)

| สิ่งที่ตรวจสอบ | คำค้น JQL |
| :--- | :--- |
| รายการงานที่ยังไม่ปิด (ไม่รวมงานของเวอร์ชัน 3.0) | `project = SCRUM AND statusCategory != Done AND fixVersion != "v3.0"` |
| รายการงานที่ปิดแล้วแต่ยังไม่กำหนด Fix Version | `project = SCRUM AND statusCategory = Done AND fixVersion is EMPTY` |
| ข้อบกพร่องที่ยังไม่ได้รับการแก้ไข | `project = SCRUM AND issuetype = Bug AND resolution = Unresolved` |
| รายการงานของ v2.0.1 ที่ยังไม่ปิด | `project = SCRUM AND fixVersion = "v2.0.1" AND statusCategory != Done` |

คำค้นสำหรับตรวจว่ารายการงานของเวอร์ชันถัดไปครบถ้วน (ควรได้ **5 รายการ**): `project = SCRUM AND labels = future-backlog`
