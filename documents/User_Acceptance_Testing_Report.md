## ส่วนที่ 3: การแยก Defect กับ New Scope (Defect vs. Scope Management)
*(อ้างอิงตาม ISO/IEC 14764: Identification & Classification ของ Modification Request)*

### 3.1 เกณฑ์การจำแนก

| ประเภท | นิยาม | การจัดการ |
| :--- | :--- | :--- |
| **UAT Defect** | ระบบทำงานขัดกับข้อกำหนดที่ตกลงไว้แล้ว (README, ขอบเขต CR-01/CR-02, ข้อความบนหน้าจอ, DoD) หรือโปรแกรมหยุดทำงาน | **ต้องแก้ไข** ออก `BUG-xxx` จัดเป็น Corrective Maintenance |
| **New Scope** | ระบบทำงานตรงตามที่ตกลงไว้ แต่ธุรกิจต้องการความสามารถใหม่ หรือต้องการเปลี่ยนสิ่งที่ออกแบบไว้โดยตั้งใจ | **ไม่แทรกใน Version 2.0** บันทึก `FB-xx` ใน Future Backlog ของสัญญา SFA-01 ไปทำใน Version 3.0 |

ระดับความรุนแรงของ Defect: **Critical** = โปรแกรมหยุดทำงานหรือข้อมูลเสียหาย · **Major** = วัตถุประสงค์หลักของเมนูใช้ไม่ได้และไม่มีทางเลี่ยงที่เหมาะสม · **Minor** = ทำงานผิดแต่มีทางเลี่ยง
